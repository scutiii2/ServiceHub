# Surface brief: ServiceHub mockup (mockup/index.html)

Mode: Operate. Standalone static mockup, synthetic data, web/index.html untouched.

Audience/job: solo owner opens a service admin UI, glances at health, rarely controls containers.
Pinned by user: clean, light and airy, whitespace, minimal chrome content first, dark mode too.

## Direction contract
THESIS: The embedded admin UI is the page; the hub frame recedes to a slim rail and one quiet bar. Refuses the heavy bordered sidebar-plus-title-bar admin template.
OWN-WORLD: Cool paper-white ground, white surfaces, hairline dividers, one ink-blue accent, green/red/amber only for state. System UI type, tabular numerals, soft 10-12px radii, no shadows beyond one popover.
STORY: Visitor sees which services are up, opens one with one click, and knows exactly what Start/Stop/Restart will touch before acting.
FIRST VIEWPORT: 248px rail left (wordmark, Add, Discover, service list with dots + container/compose tag). Main: one slim bar (name, url, container pips, actions), closeable warning strip, then the framed admin page filling the rest.
SIGNATURE: container pips, one dot per container of a compose project, coloured by state, replace prose state.
FORM: Operate, standard sidebar+content shell, seed: none (unavailable) - user pinned "clean".
FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
